CONTEXT OVERRIDE LOGIC - IMPLEMENTATION GUIDE
==============================================

PRINCIPLE: User-uploaded context documents contain PROPERTY-SPECIFIC facts that override general market data.

WHY THIS MATTERS:
- Generic market data says "County X has 2.5% property tax rate"
- User uploads a Tax Abatement Agreement showing "0% tax for 10 years, then 0.5% for 15 years"
- System MUST use the abatement data and mark Taxes/Fees as GREEN

IMPLEMENTATION STEPS:

STEP 1: IDENTIFY OVERRIDE-ELIGIBLE CRITERIA
--------------------------------------------
The following criteria are commonly subject to user document overrides:

HIGH PRIORITY (Most common):
- sub_12: Taxes and Fees (Tax Abatement Agreements, Chapter 353, TIF District docs)
- msa_15: Affordability Index (Rent Rolls showing actual tenant incomes)
- msa_9: Vacancy Rate (Rent Rolls showing actual occupancy)
- sub_13: Historical Appreciation (Appraisal reports with historical values)

MEDIUM PRIORITY:
- sub_9: Renter Density (Neighborhood studies, resident surveys)
- sub_1: Crime Rate (Private security reports, incident logs)
- msa_6: Job Diversity (Major employer announcements, economic development agreements)

STEP 2: DOCUMENT PARSING STRATEGY
----------------------------------
When user uploads context files, the AI must:

1. Extract text from PDFs/images
2. Identify document type:
   - Tax Abatement Agreement
   - Rent Roll (actual tenant data)
   - Appraisal Report
   - Economic Development Incentive
   - Government Agreement (Chapter 353, etc.)
   - HOA/CAM Fee Schedules

3. Extract key facts:
   - For Tax Docs: Effective rate, duration, conditions
   - For Rent Rolls: Current occupancy %, tenant income distribution
   - For Appraisals: Historical sale/appraisal values

STEP 3: OVERRIDE APPLICATION LOGIC
-----------------------------------
Pseudocode:

```
for each criterion in 30_point_criteria:
    market_data = get_from_perplexity_research(criterion)
    override_data = search_user_docs(criterion.metric)

    if override_data.found:
        if override_data.is_more_specific_than(market_data):
            use_value = override_data.value
            source = f"User-uploaded: {override_data.document_name}, {override_data.section}"
            override_applied = true
            override_document = override_data.document_name
        else:
            use_value = market_data.value
            source = market_data.source
            override_applied = false
    else:
        use_value = market_data.value
        source = market_data.source
        override_applied = false

    status = evaluate_against_threshold(use_value, criterion.threshold)

    return {
        "value": use_value,
        "status": status,
        "source": source,
        "override_applied": override_applied,
        "override_document": override_document if override_applied else null
    }
```

USER DOC: "Chapter 353 Agreement: 100% abatement years 1-10, 50% years 11-20, 25% years 21-25"
CRITERION: sub_12 (Taxes/Fees, threshold <2%)

LOGIC:
- Effective rate Year 1-10: 0% ✓ GREEN
- User doc is property-specific, overrides county average
- Citation: "User-uploaded: Ch353_Abatement_2023.pdf, Section 4.2"

  "override_applied": true,
  "override_document": "Ch353_Abatement_Agreement_2023.pdf"

CRITERION: msa_9 (Vacancy Rate, threshold 4-6%)

- Property outperforming market despite high MSA vacancy
- User doc shows current state, overrides market average

STEP 7: UI/UX CONSIDERATIONS
-----------------------------
In the final PDF output:
- HIGHLIGHT metrics where override_applied = true
- Include footnote: "* Based on property-specific document: [filename]"
- Visual indicator: Green checkmark or "📄 Override" icon

CRITICAL REMINDERS:
- Override logic prevents FALSE NEGATIVES (incorrectly rejecting good deals)
- User docs are FACTS, not opinions - treat as ground truth
- Always cite the specific doc and section
- If user doc is unclear/ambiguous, fall back to market data + note in reasoning
